### 3. **Graph Batch Limited to 60 Elements** ⚠️

**Configuration Found:**
```python

batch_max_elements = int(os.getenv("TABLE_GRAPH_MAX_ELEMENTS", "450"))  # Default: 450

19:48:42 - Processing graph batch 1/4 with 60 elements

19:52:49 - Processing graph batch 3/4 with 55 elements
19:52:49 - Processing graph batch 4/4 with 37 elements
```

**Total:** 60 + 57 + 55 + 37 = **209 elements** ✅ All processed

**Why 60-element limit?**

The batching logic in `_split_into_batches()` has TWO conditions:

```python
# services/document-service/app/core/enhanced_processor.py:1645-1652
def _split_into_batches(items: List[Dict[str, Any]]) -> List[List[Dict[str, Any]]]:
    for e in items:
        c = e.get('content') or ''
        # Condition 1: Max elements (450 by default)
        # Condition 2: Max characters (12000 by default) ⚠️ THIS IS TRIGGERING
        if (len(buf) >= batch_max_elements) or (total_chars + len(c) > batch_chars and buf):
            batches.append(buf)
            buf = []
            total_chars = 0
```

**Root Cause:** `TABLE_GRAPH_BATCH_CHARS=12000`
- Each table row averages ~200 characters
- After 60 rows: 60 * 200 = **12,000 characters** → triggers batch split
- This is **character-based batching**, not element-based

**Is this a problem?**
- ❌ **NO** - This is working as designed
- ✅ Prevents token limit issues in LLM calls
- ✅ First batch took 4 minutes for 60 elements
- ✅ Subsequent batches were cached (0.02s each)
- ⚠️ Could increase to 20,000 chars for faster processing

**Recommendation:**
```bash
# To increase batch size (if desired):
TABLE_GRAPH_BATCH_CHARS=20000  # From 12000
# This would create ~2 batches instead of 4
```
