Implement real-time agent message streaming with WebSocket support

PROBLEM:
- Users see only final conversation results, no intermediate progress
- No visibility into which agents are responding in real-time
- Cannot see multi-agent dialogue as it unfolds
- Long waits for conversation completion feel unresponsive
- No feedback during agent analysis phase

SOLUTION IMPLEMENTED:
Added comprehensive WebSocket streaming to AutoGen conversation flow

BACKEND CHANGES (services/ai-agent-service/app/core/autogen_copilot.py):

1. Enhanced _run_autogen_conversation() with Real-Time Streaming:
   
   Streaming Events Implemented:
   
   a) agents_prepared (conversation start):
      - Triggered when agents are initialized
      - Payload: agent_count, agent_names, message
      - Shows user which agents will participate
   
   b) conversation_running (processing):
      - Triggered when AutoGen group chat starts
      - Payload: message = Agents are analyzing your request...
      - Provides immediate feedback that processing has begun
   
   c) agent_message (real-time messages):
      - Triggered for EACH agent response as it's generated
      - Payload: source, content, timestamp, message_type, message_index, total_messages
      - Streams individual agent responses immediately
      - Works for: AutoGen messages, fallback messages, error messages
      - Includes is_fallback flag for fallback scenarios
   
   d) conversation_complete (success):
      - Triggered when all agents finish
      - Payload: total_messages, agents_participated, has_recommendations, has_actions
      - Signals conversation completion with summary
   
   e) conversation_error (failure):
      - Triggered on conversation errors
      - Payload: error, error_type, message
      - Informs user of failures with context

2. Streaming Flow Architecture:
   
   Session Detection:
   - Uses self.current_session_id from parent conversation() method
   - Checks has_websocket_connection(session_id) to enable streaming
   - Gracefully degrades if no WebSocket connection exists
   
   Message Streaming Points:
   - Agent preparation (before conversation starts)
   - Conversation start (AutoGen group chat begins)
   - Each normalized message from AutoGen result
   - Wrapped dict messages (fallback scenario)
   - Fallback simulated messages (when AutoGen unavailable)
   - Error fallback messages (exception handling)
   - Conversation completion (final summary)
   
   Logging:
   - Logs streaming enable/disable status per session
   - Logs each streamed message with source and index
   - Tracks total messages streamed for debugging

3. WebSocket Message Format:
   {
     type: agent_message,  // or agents_prepared, conversation_running, etc.
     session_id: <uuid>,
     timestamp: 2025-01-08T18:30:00.123456,
     source: migration_architect,  // agent name
     content: <agent response>,
     message_type: TextMessage,
     message_index: 0,  // position in conversation
     total_messages: 5,  // expected total
     is_fallback: false  // true if fallback mode
   }

4. Error Handling:
   - Continues if WebSocket streaming fails (logged as warning)
   - Does NOT block conversation if streaming unavailable
   - Streams error messages with error_type for diagnostics
   - Maintains fallback paths for all scenarios

TECHNICAL IMPLEMENTATION:

Session ID Propagation:
- conversation() method sets self.current_session_id = session_id
- _run_autogen_conversation() reads session_id from self.current_session_id
- Enables WebSocket lookup without parameter passing

WebSocket Check:
- has_websocket_connection(session_id) validates active connection
- Returns False if WebSocket not available or session not connected
- Prevents unnecessary streaming attempts

Streaming Method:
- stream_message_to_websocket(session_id, message_type, data)
- Adds type, session_id, timestamp automatically
- Calls websocket_manager.send_message()
- Catches exceptions to prevent conversation failure

Message Normalization:
- Existing _normalize_autogen_message() creates uniform message structure
- Streaming uses normalized message dict directly
- Ensures consistency between streamed and final messages

STREAMING SCENARIOS:

1. Normal AutoGen Flow:
   - agents_prepared → conversation_running → agent_message (multiple) → conversation_complete

2. Fallback Simulated Flow:
   - agents_prepared → conversation_running → agent_message (fallback) → conversation_complete

3. Error Fallback Flow:
   - agents_prepared → conversation_running → agent_message (error fallback) → conversation_complete

4. Critical Error Flow:
   - agents_prepared → conversation_error

USER EXPERIENCE IMPACT:

Before:
- User sends message → long wait → all responses appear at once
- No indication of progress during analysis
- Cannot see which agents are working
- Feels like black box processing

After:
- User sends message → immediate agents prepared notification
- See conversation running status
- Each agent response appears in real-time as generated
- See which agent is responding (source field)
- Progress indicators show message_index/total_messages
- Conversation completion confirmation
- Error notifications if something fails

COMPATIBILITY:

- Backward compatible: works without WebSocket connection
- Graceful degradation: no streaming if WebSocket unavailable
- No breaking changes to existing conversation() API
- Existing REST endpoints continue to work
- Frontend can opt-in to streaming by connecting WebSocket

DEPENDENCIES:

- Requires WebSocket connection via websocket_manager
- Uses existing stream_message_to_websocket() method
- Leverages has_websocket_connection() check
- No new external libraries required

LOGGING ENHANCEMENTS:

- Logs WebSocket streaming enable/disable per session
- Logs each streamed message count and source
- Tracks total messages for debugging
- Warnings if streaming fails (non-blocking)

NEXT STEPS FOR FRONTEND:

3. Display messages in real-time as they arrive
4. Update UI with progress indicators (message_index/total_messages)
5. Show conversation_complete notification

Example Frontend WebSocket Handler:
socket.on(agent_message, (data) => {
  // Add message to UI immediately
  addMessage({
    source: data.source,
    content: data.content,
    timestamp: data.timestamp,
    progress: data.message_index + 1 + / + data.total_messages
  });
});
